# 数字员工自我进化机制

`dsh-org-panel` 的员工从 v1.2 开始拥有独立的长期记忆、技能档案与插件学习记录。目标不是让 Agent 随机修改自己的系统提示词，而是让成长过程可持久化、可验证、可回忆、可复用。

## 1. 三层记忆

### 会话记忆

每位员工继续复用 DSH `continuable subagent`，保持同一个员工会话的上下文连续性。

### 长期记忆

Host 侧 `EvolutionStore` 默认写入：

```text
~/.dsh-org-panel/evolution.json
```

也可以通过 `DSH_ORG_PANEL_MEMORY_FILE` 或插件配置 `memoryFile` 指定路径。

长期记忆包含：

- `preference`：老板或用户稳定偏好
- `project`：项目事实与历史任务
- `lesson`：踩坑与复盘经验
- `workflow`：可复用工作流
- `fact`：需要长期保留的事实
- `relationship`：团队协作关系

任务开始前，员工会检索相关记忆；真正有长期价值的内容才会写入，避免把全部聊天记录当“记忆”。

### 技能记忆

每位员工拥有独立技能档案：技能名、来源、绑定工具、插件名、成功/失败次数、等级和经验值。

员工完成任务、复盘、验证工具时会积累 XP，并形成 `Lv.1 ~ Lv.10` 的成长记录。

## 2. 自我进化协议

员工 persona 内置以下学习循环：

```text
任务 → 回忆历史经验 → 扫描可用工具 → 执行 → 验证 → 复盘 → 写入长期记忆 / 升级技能
```

关键原则：

1. 不允许为了“进化”伪造经验。
2. 插件或工具必须在当前 Runtime 中真实存在，才允许绑定到员工技能。
3. 成功与失败都可成为经验，失败记录会降低重复踩坑概率。
4. 员工私有记忆只用于工作上下文，不会机械地在每次回复中复述。

## 3. 新增 Host 工具

| 工具 | 用途 |
| --- | --- |
| `staff_memory_recall` | 检索员工长期记忆 |
| `staff_memory_remember` | 写入偏好、事实、经验、工作流 |
| `staff_skill_learn` | 将已验证工具/插件绑定为员工技能 |
| `staff_reflect` | 任务复盘并增加成长经验 |
| `staff_profile` | 查看员工等级、记忆、技能、插件和最近复盘 |
| `staff_capability_scan` | 扫描当前 Runtime 已暴露的真实工具能力 |

## 4. 插件市场连接方式

`staff_capability_scan` 不假装自己是另一个插件市场。它读取 DSH 当前 Runtime 中真实注册的工具，并按来源归类：

- DSH / Cordis 插件
- MCP
- 搜索 / Web
- 创意类插件（图片、视频、音频、FAL、Canva、Figma 等）
- 外部连接器（GitHub、Gmail、Calendar、Notion、Slack 等）
- 工程工具

因此推荐流程是：

```text
安装/启用插件或 MCP
    ↓
插件向 DSH 暴露真实 Tool
    ↓
staff_capability_scan 发现能力
    ↓
员工实际调用并验证
    ↓
staff_skill_learn 绑定为长期技能
    ↓
后续任务自动记得该能力
```

当前版本不会在没有稳定 Host Marketplace API 的情况下擅自安装第三方插件。自动安装应该由未来的 Marketplace Adapter 完成，并继续遵守“真实安装后才能学会”的约束。

## 5. 扩展员工

默认员工已扩展为 15 人：

- 秘书：总裁秘书
- 老王：技术经理
- 小周：招聘负责人
- 小刘：程序员
- 阿明：产品经理
- 小丽：市场调研
- 大壮：平台工程师 / 插件能力接入
- 静静：文档专员
- 阿搜：搜索专家
- 小画：视觉设计师
- 阿镜：视频导演
- 南枝：小说编剧
- 柚子：自媒体主编
- 小数：数据分析师
- 小麦：增长运营

每个员工都有自己的基础能力、工具偏好、长期记忆和成长档案。新增岗位仍然可以通过 composition 的 `staff` / `roles` 配置覆盖。
