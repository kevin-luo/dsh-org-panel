## 1. Product purpose

在 DeepSeek Harness 当前会话内，把秘书和多名独立子代理模拟成一家可交互、可观察、可持续工作的赛博公司。

## 2. Primary user

需要在桌面端长时间指挥多个 AI 员工、查看执行过程并直接点名沟通的老板或技术负责人。

## 3. Principles

1. **真人设先于装饰。** 每位员工必须是独立代理；办公室动画只能反映真实状态，不能替代真实执行。
2. **一个公司，一个会话。** 对话、思考、工具轨迹和办公室统一在当前 Tab，永远只使用 Harness 原生输入框。
3. **办公室必须在营业。** 工位、组织关系、时钟、制度和生活动线共同表达公司正在运转。
4. **信息密集但层次明确。** 老板先看到公司状态，再看到组织与员工，最后深入任务和轨迹。
5. **幽默来自职场细节。** 标语和员工行为可以有梗，但不能损害状态真实性和可用性。

## 4. Success metric

老板进入页面后 15 秒内能判断谁在工作、谁在摸鱼、公司当前时间和组织归属，并能通过一次 @ 点名与秘书或任一真实员工开始对话。

## 5. Out of scope

- 不创建第二个聊天输入框
- 不使用其他开源项目的名称或品牌元素
- 不用静态剧本伪造员工交付
- 不让秘书冒充专业员工

## 6. Learned constraints

- **2026-08-15** — 当前 Tab 必须原生完成对话、思考与轨迹，不跳转“对话”Tab，也不复制输入框。*原因：工作台本身就是主操作面。*
- **2026-08-15** — 点名员工必须由对应独立子代理本人回复。*原因：角色存在的价值是持续人格和真实分工。*
- **2026-08-15** — 不出现 Star Office 或其他仓库品牌。*原因：参考只提供交互灵感，产品身份属于本插件。*
- **2026-08-15** — 主 Agent 显示为秘书，并出现在 @ 名单。*原因：秘书是公司的接待与协调中枢。*
- **2026-08-15** — 办公室要模拟真实职场生活，包括作息、工位、电脑、会议、厕所、抽烟和放风。*原因：状态可视化要有真实空间和日常行为。*
- **2026-08-15** — 办公室与工作群必须在同一视口内同时可见并各自滚动，不能靠上下长页面二选一观看。*原因：老板需要一边观察员工状态，一边持续对话。*
- **2026-08-17** — 聊天记录是工作台主内容，办公室降为最右侧的窄状态侧栏。*原因：办公室负责解释状态，任务沟通、思考与工具轨迹才是老板的主要工作。*
- **2026-08-15** — 员工移动必须遵循岗位、工作状态、固定工位、出发/停留/返回路线，禁止按随机或短周期取模无序换位。*原因：动画承担状态解释，不是屏保。*
- **2026-08-15** — 老板明确 @ 某员工时，界面呈现为老板与本人直聊，不显示秘书转交话术；秘书只处理未点名消息和组织统筹。*原因：点名就是直接沟通，不应增加虚假的中间层。*
- **2026-08-15** — 像素员工必须能通过发型、服装、配色和岗位配件一眼区分。*原因：多角色可视化不能只靠名字标签。*
